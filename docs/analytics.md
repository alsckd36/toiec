## 풀이 기록

신규 파일 answer-history-v1.json(version 1)에 실제 제출만 저장합니다.
각 기록은 제출 ID, 단어 ID, DAILY/CUSTOM/REVIEW 구분, 회독(오늘의 학습만), 단어의 DAY,
선택/정답 전문, 정답 여부, 제출 시각(ZonedDateTime의 오프셋·시간대 포함), 제출 당시 현지 날짜를 포함합니다.
시각은 버튼 제출 시점에 캡처하며 저장 재시도는 최초의 저장된 답·시각을 유지합니다.
맞춤/오답 복습은 세션 UUID + 문제 인덱스, 오늘의 학습은 저장된 일일 세션 토큰 + 인덱스를 제출 ID로 사용합니다.
같은 단어·DAY의 새 세션/새 회독은 새로운 제출이며 이전 정답과 관계없이 기록합니다.
오늘의 학습 재실행으로 이미 수락한 답을 다시 표시하거나 같은 저장을 재시도해도 동일 ID를 중복 기록하지 않습니다.
화면 표시·이동·채점 재표시·발음에는 기록 API를 호출하지 않습니다.

오답 업데이트와 일일 진행 파일의 변경 사항을 기록 파일의 pending journal에 함께 원자적으로 저장합니다.
기록 저장 후 오답/진행 쓰기가 중단되면 다음 진입·재시도 때 같은 효과를 복구하고 pending을 지웁니다.
임시 파일·fsync·원자적 교체를 사용하며 저장 실패를 조용히 넘기거나 기존 파일을 초기화하지 않습니다.
복구된 오늘의 학습 답은 미응답 문제 목록에서 건너뛰어 중복 증가를 막습니다.
오답노트 삭제/복습 제거와 풀이 기록은 분리되어 과거 제출은 삭제되지 않습니다.
기능 추가 전 오답/일일 답변을 읽어 통계를 만들어내지 않습니다. 신규 기록 파일이 없으면 0건입니다.
앱 업데이트는 파일을 유지합니다. 앱 삭제/데이터 삭제는 기존 규칙대로 데이터를 삭제하므로 업데이트 설치하세요.

## 집계·그래프

오늘을 포함한 현지 날짜 7개를 만들고 각 기록의 저장된 localDate로 그룹화합니다.
전체 수=정답 수+오답 수, 정답률=정답 수/전체 수*100이며 학습별 비율을 평균하지 않습니다.
반복 풀이를 모두 포함하고 날짜를 넘긴 답은 각각의 제출 날짜에 집계합니다.
과거 날짜는 현재 시간대로 다시 변환하지 않습니다. 앱 복귀, 홈 진입, 제출 후 및 분 단위로 오늘 표시를 새로 계산합니다.

정답률 축은 0·25·50·75·100%입니다. 답변 없는 날짜는 null이며 점과 양옆 연결선을 만들지 않습니다.
실제 오답만 있는 날짜의 0%는 점을 표시합니다.
문제 수는 정답(민트) 아래, 오답(회색) 위의 날짜별 누적 막대이며 전체 수(짙은 선)를 같은 축에 그립니다.
날짜별 합계이며 이전 날짜까지의 누적 총량이 아닙니다. 기록 없는 날은 0개입니다.
각 카드의 점/막대 또는 접근 가능한 날짜 버튼을 누르면 날짜와 정확한 수치를 표시합니다.
정답률은 소수점 1자리까지 표시하며 전체/정답/오답 개수도 함께 확인할 수 있습니다.

세로축은 고정하고 날짜 영역은 작은 화면·큰 글꼴에서 가로 스크롤합니다.
최소 날짜 터치 너비 48dp를 유지하고 축·날짜·범례·상세를 확대 글꼴에 맞춰 줄바꿈/스크롤합니다.
홈은 LazyColumn으로 세로 스크롤하며 분석 카드를 별도 웹 화면으로 열지 않습니다.
전체 기록이 없으면 ‘아직 학습 기록이 없어요’, 정답률 —, 문제 수 0개와 기존 오늘의 학습 시작/이어하기를 호출하는 학습 시작 버튼을 표시합니다.
실제 앱에 가짜 예시 데이터를 넣지 않았습니다.

## 실제 화면 검증

AnalyticsFlowTest는 실제 앱 버튼으로 오늘의 학습에서 3정답·1오답을 제출해 4개·75%를 확인하고 PNG를 캡처했습니다.
그래프/날짜 터치, 기록 없는 날짜 선택, 같은 답 중복 입력, 화면·발음 요청이 기록을 늘리지 않는 것도 확인했습니다.
이후 미응답 문제 이어하기, 두 번의 맞춤학습 재진입, 오답 복습을 실제 제출해 총 8개(정답 6·오답 2)를 저장했습니다.
AnalyticsRestartTest는 am force-stop 뒤 별도 instrumentation 프로세스에서 8개/75% 및 오늘의 학습 5문제 진행이 복원되는지 확인합니다.
캡처의 4개와 8개는 실제 테스트 제출에서 생긴 수치이며 앱에 예시 데이터로 포함하지 않습니다.

큰 글꼴 테스트는 동일한 운영 StudyContent의 빈 기록 레이아웃을 LocalDensity fontScale=2.0, 폭 480dp 및 320dp로 렌더링한 fixture입니다.
Android 기기 전체 font_scale 설정을 바꾸거나 가짜 풀이를 실제 기록 파일에 넣지 않았습니다.
날짜 버튼·상세 글자의 TextLayoutResult에서 잘림이 없는지, 두 방향 스크롤과 날짜 터치가 가능한지 검사합니다.
초기 실행에서 축이 스크롤 영역과 함께 사라지는 문제를 수정해 축을 고정했습니다.
큰 글꼴 날짜의 폭 반올림으로 생긴 작은 overflow도 발견하여 날짜 텍스트를 버튼 폭에 맞춰 중앙 정렬했습니다.
좁은 화면에서 처음 보이는 날짜가 중간부터 잘리지 않도록 표시 가능한 날짜 수에 맞춰 셀 너비를 계산합니다. 드래그 중 일부 날짜가 화면 밖에 있는 것은 가로 스크롤의 정상 동작입니다.

검증 환경: API 30 Android 11, 480×800/density 160, -no-window -accel off -gpu swiftshader 소프트웨어 에뮬레이터.
물리 휴대폰은 실행하지 않았습니다. 실제 시스템 날짜 변경은 하지 않았고 자정·시간대 변경은 주입 시계의 JVM 테스트로 확인했습니다.
영어 TTS 데이터가 없는 에뮬레이터에서는 설치 안내를 표시하며 세 학습 방식 모두 정상 동작했습니다. 실제 음성 출력은 확인하지 못했습니다.
